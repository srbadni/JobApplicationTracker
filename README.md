# Job Application Tracker API

A FastAPI service organized by business feature for the Job Application Tracker
project.

## Architecture

```text
app/
├── api/                 # API router composition and version boundary
├── core/                # Configuration and cross-cutting infrastructure
├── features/            # Feature-local routes, schemas, and business logic
│   └── health/
├── schemas/             # Contracts shared across multiple features
└── main.py              # Application factory
main.py                  # ASGI compatibility entry point
```

New functionality should normally be added as a folder under `app/features`.
Keep its HTTP adapter in `router.py`, request/response contracts in `schemas.py`,
and framework-independent business logic in `service.py`. Only move a component
to `app/core` or `app/schemas` after it is genuinely shared by multiple features.

This structure applies FastAPI's official guidance for
[larger applications with `APIRouter`](https://fastapi.tiangolo.com/tutorial/bigger-applications/),
[cached settings dependencies](https://fastapi.tiangolo.com/advanced/settings/),
and [dependency overrides in tests](https://fastapi.tiangolo.com/advanced/testing-dependencies/).
It deliberately avoids adding repository/database layers before a feature needs
them; boundaries should follow actual behavior rather than empty abstractions.

## Install

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the virtual environment with:

```powershell
.venv\Scripts\activate
```

The application has safe development defaults. To override them, copy
`.env.example` to `.env`; environment variables take precedence over that file.

## Run

```bash
uvicorn main:app --reload
```

The health endpoint is available at:

```text
GET /api/v1/health
```

Create the PostgreSQL schema before starting the API:

```bash
alembic upgrade head
```

Companies can then be created with `POST /api/v1/companies`. The endpoint
accepts a required `name`, plus optional `description` and HTTP(S) `website`
fields; identifiers and timestamps are generated by PostgreSQL.

## Test

Tests currently live next to their related features instead of in a separate
`tests` directory. The application factory and FastAPI dependency overrides keep
them isolated from process-global configuration.

```bash
pytest
```
